4  Week 4: Data Frames and Plotting

Three weeks of machinery: vectors and matrices (Chapter 1), loops (Chapter 2), functions (Chapter 3). This week we point all of it at what statisticians actually spend their days on: tables of data. We will learn how to store data in data frames, manipulate them with dplyr (in Python: pandas), and — at last — plot them properly with ggplot2 (in Python: plotnine). The quick-and-dirty plot() and plt.plot() calls from the previous weeks retire this week.

4.1 The tidyverse

Modern data work in R happens largely inside the tidyverse, a collection of packages that share a common design: dplyr for manipulation, readr for import/export, tibble for nicer data frames, ggplot2 for graphics, and purrr, which you already met in Chapter 3.

Note for Python users: Python spreads the same jobs over separate packages: pandas covers what dplyr, readr and tibble do, and plotnine is a deliberate port of ggplot2 — same grammar, nearly the same code. Together with numpy they are this week’s toolkit, installed and imported alongside the R column below.

Install it once (already done on university machines):

R

install.packages("tidyverse")

Python

!python -m pip install pandas plotnine

then load it at the top of every script:

R

library(tidyverse)

Python

# several packages instead of one — import them together, at the top
import numpy as np
import pandas as pd
from plotnine import (
    ggplot, aes, geom_point, geom_smooth, geom_histogram, geom_boxplot,
    geom_line, geom_hline, facet_wrap, labs, theme_minimal
)

Installing happens once per computer; loading happens once per session — a distinction everyone mixes up exactly once.

4.2 Data frames

A data frame is a table: each column is a named vector, and different columns may hold different types (numeric, character, logical). This is the crucial difference from the matrices of Chapter 1, where every entry had to share one type. In statistics-speak, columns are variables and rows are observations.

4.2.1 Building one

Here is a small dataset of plant-based milks and their nutritional content per 250 ml glass:

type calories protein fibre carbs sugars fat
Almond 60 1 1 8 7 2.5
Soy 100 7 2 10 NA 4
Oat 120 3 NA 20 19 2.5
Rice 130 1 NA 25 NA 2.5

Note the NAs: real data is rarely complete, and R has a dedicated value for “not available” (in Python, pandas marks missing numbers with the floating-point NaN, written np.nan). We build the data frame column by column with data.frame() — in Python, from a dictionary mapping column names to lists:

R

# each argument is one column (a vector); all must have the same length
milk <- data.frame(
  type     = c("Almond", "Soy", "Oat", "Rice"),
  calories = c(60, 100, 120, 130),
  protein  = c(1, 7, 3, 1),
  fibre    = c(1, 2, NA, NA),
  carbs    = c(8, 10, 20, 25),
  sugars   = c(7, NA, 19, NA),
  fat      = c(2.5, 4, 2.5, 2.5)
)
milk

4   Rice      130       1    NA    25     NA 2.5

4.2.2 Columns, rows and cells

Single columns come out with the dollar syntax in R and single square brackets in Python, returning a plain vector (in pandas: a Series):

R

milk$calories
[1]  60 100 120 130

Python

milk["calories"]
0     60
1    100
2    120
3    130
Name: calories, dtype: int64

In R, square brackets with a column name return instead a smaller data frame — pandas does the same when you double the brackets:

R

milk["calories"]           # still a data frame
  calories
1       60
2      100
3      120
4      130
milk[c("type", "protein")] # two columns, still a data frame
    type protein
1 Almond       1
2    Soy       7
3    Oat       3
4   Rice       1

Python

milk[["calories"]]          # double brackets: still a data frame
   calories
0        60
1       100
2       120
3       130
milk[["type", "protein"]]   # two columns, still a data frame
     type  protein
0  Almond        1
1     Soy        7
2     Oat        3
3    Rice        1

Note for Python users: the single/double bracket split is worth committing to memory: milk["calories"] is a Series (the vector-like object), milk[["calories"]] is a one-column DataFrame. The attribute shorthand milk.calories also works, but only for names that are valid Python identifiers — brackets are the safe habit.

For rows (and row/column combinations) we index in two dimensions, exactly as we did with matrices: df[rows, columns], with an empty slot meaning “everything”:

R

milk[2, ]                        # second row, all columns
  type calories protein fibre carbs sugars fat
2  Soy      100       7     2    10     NA   4
milk[1:2, c("type", "calories")] # first two rows, two columns
    type calories
1 Almond       60
2    Soy      100

Python

milk.iloc[[1]]                       # second row: position 1 — Python counts from 0!
  type  calories  protein  fibre  carbs  sugars  fat
1  Soy       100        7    2.0     10     NaN  4.0
milk.loc[0:1, ["type", "calories"]]  # first two rows, two columns
     type  calories
0  Almond        60
1     Soy       100

Note for Python users: pandas splits two-dimensional indexing over two indexers: .iloc takes integer positions (0-based, end excluded — the rules of Chapter 1), while .loc takes labels — here the row labels happen to be the integers 0, 1, 2, … — and includes both ends, which is why 0:1 above returns two rows. Also, milk.iloc[1] without the inner brackets squeezes the row into a Series; the doubled brackets keep it a one-row DataFrame.

The comparison operators of Chapter 2 work here too — a logical vector selects rows:

R

# rows where calories exceed 100
milk[milk$calories > 100, ]
  type calories protein fibre carbs sugars fat
3  Oat      120       3    NA    20     19 2.5
4 Rice      130       1    NA    25     NA 2.5

Python

# rows where calories exceed 100
milk[milk["calories"] > 100]
   type  calories  protein  fibre  carbs  sugars  fat
2   Oat       120        3    NaN     20    19.0  2.5
3  Rice       130        1    NaN     25     NaN  2.5

summary() counts the NAs for us — and those NAs are contagious. Any computation touching a missing value returns NA, unless you explicitly ask R to drop them:

R

mean(milk$sugars)               # NA: R refuses to guess
[1] NA
mean(milk$sugars, na.rm = TRUE) # mean of the observed values
[1] 13

Python

milk["sugars"].mean()               # pandas skips NaN by default!
np.float64(13.0)
milk["sugars"].mean(skipna=False)   # the R-style refusal is opt-in
np.float64(nan)

Note for Python users: the two languages picked opposite defaults: R propagates NA until you say na.rm = TRUE; pandas silently skips NaN until you say skipna=False. Neither is wrong, but know which one you are getting — a summary that quietly ignores missing values can hide a data problem R would have shouted about.

4.3 Tibbles

The tidyverse ships a modernised data frame called a tibble. It is a data frame — everything above applies — with two behavioural upgrades. First, printing: a tibble shows ten rows, only the columns that fit, and the type of each. A classic data frame would happily dump every last row of a 50,000-row dataset into your console. Second, no partial matching. Watch this data.frame quirk:

R

milk$cal   # base data frame: silently matches "calories"!
[1]  60 100 120 130

Python

milk["cal"]   # pandas never guesses: unknown column, immediate error
KeyError: 'cal'

That is a bug waiting to happen — mistype a column name and R may “helpfully” return a different column. A tibble warns you and returns NULL:

R

as_tibble(milk)$cal
Warning: Unknown or uninitialised column: `cal`.
NULL

Python

print(milk.get("cal"))   # the forgiving lookup: None (Python's NULL)
None

Note for Python users: there is no tibble to reach for because there is no quirk to fix — pandas has exactly one table type, the DataFrame you have been using all along, and it never partial-matches (as the KeyError above shows; .get() is the polite version). The genuinely new thing to watch is the index: every DataFrame carries row labels — the unnamed left column in the printouts — which stick to their rows through filtering and sorting. It is pandas’ (heavily used) version of R’s (rarely used) row names; when it gets in your way, .reset_index() demotes it to an ordinary column, and index=False keeps it out of your CSV files. Both will appear below.

You create tibbles directly with tibble() (same syntax as data.frame(), with the bonus that later columns can use earlier ones), or convert with as_tibble(). From now on we work with tibbles, and we need a bigger dataset to play with: mtcars, a built-in table of 32 cars from a 1974 issue of Motor Trend (in Python it ships with plotnine, as plotnine.data.mtcars). The variables we will use most: mpg (miles per gallon — higher means more fuel-efficient), cyl (cylinders), hp (horsepower), wt (weight, 1000 lbs), qsec (quarter-mile time in seconds), am (transmission: 0 automatic, 1 manual).

read_csv() reads the file, guesses each column’s type (it prints its guesses — read them, they catch import bugs early), and returns a tibble. Base R has read.csv() — dot, not underscore — which does the same job into a plain data frame, more slowly on large files. Recall from Chapter 1 that a bare filename like "week4_milk.csv" is relative to your working directory — if the file cannot be found, getwd() (Python: os.getcwd()) is the first thing to check.

Note for Python users: two things in the chunk above. First, the filename: throughout these notes the Python column writes _py files (week4_milk_py.csv) so the two languages never overwrite each other’s output. Second, index=False: without it pandas saves the index as an anonymous extra column, which comes back to haunt you at reading time. pd.read_csv() guesses column types just like readr — but silently; run .info() on an import when it matters.

4.5 The pipe |>

Data analysis is a sequence of steps, and code reads best when it is written in the order the steps happen. The pipe operator |> takes the value on its left and passes it as the first argument of the function on its right — programming’s version of function composition (f_2 \circ f_1)(x), which we met in Chapter 3. So to compute \ln(1 + 2 + \dots + 10):

R

x <- 1:10
x |> sum() |> log()   # same as log(sum(x))
[1] 4.007333

Python

x = np.arange(1, 11)
np.log(x.sum())       # no pipe in Python: nest the calls, or chain methods
np.float64(4.007333185232471)

Read it left to right: “take x, sum it, take the log”. Further arguments go in their usual place, after the piped-in first one:

R

x |> sum() |> log(base = 10)   # same as log(sum(x), base = 10)
[1] 1.740363

Python

np.log10(x.sum())     # numpy's dedicated base-10 logarithm
np.float64(1.7403626894942439)

In the wild you will also meet %>%, the older pipe from the magrittr package — for our purposes it does the same thing, but write the native |>.

The pipe matters this week because every dplyr verb takes a data frame as its first argument and returns a data frame: they are built to be piped.

Note for Python users: Python has no pipe operator; the idiom that plays its role is method chaining. Every pandas verb below is a method that returns a new DataFrame, so a pipeline reads left to right as cars.query(...).assign(...).sort_values(...) — dots instead of pipes. Wrap a chain in parentheses to split it over several lines, one verb per line; you will see that layout constantly from here on.

4.6 Data manipulation with dplyr (and pandas)

dplyr provides one verb per manipulation you would want to do to a table:

Verb Action pandas counterpart
filter() keep a subset of the rows .query() / boolean mask
select() keep a subset of the columns [[...]] double brackets
mutate() add new columns computed from existing ones .assign()
arrange() reorder the rows .sort_values()
summarise() collapse rows down to summary statistics .agg()

Inside a verb you refer to columns by bare name — no cars$ prefix needed; dplyr knows to look inside the data frame first. (One side effect of loading the tidyverse: its filter() masks the base function of the same name. If filter() ever behaves strangely, be explicit and call dplyr::filter().)

Note for Python users: pandas gives you the bare-name comfort only inside .query(), whose condition is a string evaluated inside the data frame. Elsewhere columns are spelled cars["mpg"] — and inside a chain, where the intermediate data frame has no name, .assign() accepts functions of it (lambda df: ...). Both appear below.

R

cars <- cars |>
  mutate(

    am  = factor(am, labels = c("automatic", "manual")),
    vs  = factor(vs, labels = c("V-shaped", "straight"))

cars = cars.assign(

4.6.3 group_by and summarise

summarise() collapses a data frame to summary statistics — n() counts the rows, and any vector-to-number function (mean, sd, median, min, …) works:

R

cars |> summarise(n = n(), mean_mpg = mean(mpg), sd_mpg = sd(mpg))

  <int>    <dbl>  <dbl>

Python

# ungrouped: pick the column, name the summaries
cars["mpg"].agg(n = "size", mean_mpg = "mean", sd_mpg = "std")
n           32.000000
mean_mpg    20.090625
sd_mpg       6.026948
Name: mpg, dtype: float64

On its own this is a glorified mean(). The power move is group_by(): it splits the data frame into groups by the values of one or more columns, so that summarise() produces one row per group. Group means and group spreads are the first step of nearly every statistical analysis, and here they cost one pipeline:

R

cars |>
  group_by(am) |>
  summarise(n = n(), mean_mpg = mean(mpg), sd_mpg = sd(mpg))
# A tibble: 2 × 4

1 automatic    19     17.1   3.83
2 manual       13     24.4   6.17

Python

(
  cars
  .groupby("am", observed=True)
  .agg(n        = ("mpg", "size"),
       mean_mpg = ("mpg", "mean"),
       sd_mpg   = ("mpg", "std"))
  .reset_index()
)
          am   n   mean_mpg    sd_mpg
0  automatic  19  17.147368  3.833966

4.7 Plotting with ggplot2 (and plotnine)

ggplot2 implements the grammar of graphics: instead of memorising one function per chart type, you describe a plot with three ingredients:

  • the data: a data frame;
  • the aesthetic mapping aes(): which variables map to which visual channels — x-position, y-position, colour, fill, shape;
  • the geometries geom_*(): how the mapped data is drawn — points, lines, bars, boxes.

Layers are glued together with + (a historical quirk: ggplot2 predates the pipe). Swap the geometry and the same data-to-aesthetics mapping becomes a different plot; that is the whole grammar. Easier done than said:

Note for Python users: plotnine is a faithful port of ggplot2: same grammar, same function names, same +. Two mechanical differences only: column names inside aes() are quoted strings — aes(x="wt", y="mpg") — and a plot spread over several lines needs wrapping parentheses (plus .show() to display it from a script). Both spellings of colour/color work, in either language.

4.7.1 Scatter plots

R

ggplot(cars, aes(x = wt, y = mpg)) +
  geom_point()

Python

(
  ggplot(cars, aes(x="wt", y="mpg")) +
  geom_point()
).show()

Dissecting it: ggplot(cars, ...) starts a plot from the cars data; aes(x = wt, y = mpg) maps weight to the x-axis and fuel consumption to the y-axis; + geom_point() draws one point per row. Heavier cars burn more fuel — a relationship crying out for a line through it:

R

ggplot(cars, aes(x = wt, y = mpg)) +
  geom_point() +
  geom_smooth(method = "lm", se = FALSE)

Python

(
  ggplot(cars, aes(x="wt", y="mpg")) +
  geom_point() +
  geom_smooth(method="lm", se=False)
).show()

geom_smooth(method = "lm") overlays the least-squares regression line — the line minimising the sum of squared vertical distances to the points, the same fit you would get from R’s lm(mpg ~ wt, data = cars) (in Python, from statsmodels, which is exactly what plotnine’s method="lm" calls under the hood). Fitting models by minimising a loss is precisely the business of Chapter 5.

To bring in a third variable, map it to a third aesthetic:

R

ggplot(cars, aes(x = wt, y = mpg, colour = am)) +
  geom_point()

Python

(
  ggplot(cars, aes(x="wt", y="mpg", colour="am")) +
  geom_point()
).show()

One extra word in aes() bought us a coloured grouping and a legend.

4.7.2 Mapping vs setting aesthetics

There are two ways to control colour, and mixing them up is the most common ggplot bug in existence. Mapping (inside aes()) ties an aesthetic to a variable; setting (outside aes(), inside the geom) fixes it to a constant:

R

# setting: every point steelblue, no legend — a constant, so OUTSIDE aes()
ggplot(cars, aes(x = wt, y = mpg)) +
  geom_point(colour = "steelblue")

Python

# setting: every point steelblue, no legend — a constant, so OUTSIDE aes()
(
  ggplot(cars, aes(x="wt", y="mpg")) +
  geom_point(colour="steelblue")
).show()

Put a constant inside aes() and ggplot does something legal but absurd: it invents a variable whose every value is the string "blue", and dutifully assigns it the first default colour — which is red:

R

# the classic mistake: "blue" is not a variable
ggplot(cars, aes(x = wt, y = mpg, colour = "blue")) +
  geom_point()

Python

# the classic mistake: "blue" is not a variable
(
  ggplot(cars, aes(x="wt", y="mpg", colour='"blue"')) +
  geom_point()
).show()

If your plot sports a legend titled "blue" full of red points, you now know why.

Note for Python users: mind the doubled quotes in aes(colour='"blue"'). plotnine evaluates aes() strings as expressions, so the inner quotes are what make "blue" a constant string — a plain aes(colour="blue") would go looking for a column called blue and raise an error instead of drawing red points. Different failure, same moral: constants do not belong in aes().

4.7.4 Line plots

geom_line() connects observations in x-order — the right geometry when x is time, iteration count, or anything sequential. Let’s watch the law of large numbers in action: simulate 10000 fair-coin flips (rbinom(10000, size = 1, prob = 0.5) in R, rng.binomial(1, 0.5, size=10000) in Python — both draw 10000 independent 0/1 values) and plot the running proportion of heads. Since randomness is involved, we set the seed so that each “random” figure is exactly reproducible — though not the same figure: R’s and numpy’s generators produce different streams, so the two columns show two different, equally fair, coin sequences:

R

set.seed(7432)
lln <- tibble(
  n            = 1:10000,
  running_mean = cumsum(rbinom(10000, size = 1, prob = 0.5)) / n
)

ggplot(lln, aes(x = n, y = running_mean)) +
  geom_line() +
  geom_hline(yintercept = 0.5, linetype = "dashed")

Python

rng = np.random.default_rng(7432)
n = np.arange(1, 10001)
lln = pd.DataFrame({
    "n":            n,
    "running_mean": np.cumsum(rng.binomial(1, 0.5, size=10000)) / n
})

(
  ggplot(lln, aes(x="n", y="running_mean")) +
  geom_line() +
  geom_hline(yintercept=0.5, linetype="dashed")
).show()

In both runs the wild early swings settle onto the dashed line at 1/2: the sample mean converging to the expectation — slowly, as the fluctuations only shrink like 1/\sqrt{n}. (geom_hline() draws a horizontal reference line; note how it stacks onto the plot as just another layer.) In Chapter 5 the very same plot template — value against iteration — will track optimisation algorithms as they converge.

Note for Python users: watch the argument names — they swap roles across the languages. R’s rbinom(10000, size = 1, prob = 0.5) asks for 10000 draws of size = 1 trial each; numpy’s rng.binomial(1, 0.5, size=10000) says the same thing, but now size counts the draws. Copying arguments across languages by name, without reading, is how “10000 flips of one coin” silently becomes “one flip of 10000 coins”.

4.7.5 Facets

Colour handles a third variable; a fourth would get crowded. Faceting splits one plot into a panel per value of a variable, with shared axes so panels compare fairly:

R

ggplot(cars, aes(x = wt, y = mpg, colour = am)) +
  geom_point() +
  facet_wrap(~ cyl)

Python

(
  ggplot(cars, aes(x="wt", y="mpg", colour="am")) +
  geom_point() +
  facet_wrap("~cyl")
).show()

facet_wrap(~ cyl) means “one panel per value of cyl” (the ~ is R’s formula syntax — you will meet it again in regression). Arrange the panels with nrow or ncol, e.g. facet_wrap(~ cyl, ncol = 1) stacks them vertically, which is ideal for comparing distributions along a shared x-axis.

Note for Python users: plotnine takes the formula as a string — facet_wrap("~cyl"), or just facet_wrap("cyl") — with the same nrow/ncol arguments.

4.7.6 Labels, themes and saving

Everything so far was exploratory: quick plots for you. A figure for a report needs proper labels — nobody downstream knows what wt means — and a cleaner look. labs() names every mapped aesthetic plus the title, and theme_minimal() swaps the grey default for something publication-friendly (we will use it from now on):

R

p <- ggplot(cars, aes(x = wt, y = mpg, colour = am)) +
  geom_point() +
  labs(
    title  = "Lighter cars go further on a gallon",
    x      = "Weight (1000 lbs)",
    y      = "Miles per US gallon",
    colour = "Transmission"
  ) +
  theme_minimal()
p

Python

p = (
  ggplot(cars, aes(x="wt", y="mpg", colour="am")) +
  geom_point() +
  labs(
      title  = "Lighter cars go further on a gallon",
      x      = "Weight (1000 lbs)",
      y      = "Miles per US gallon",
      colour = "Transmission"
  ) +
  theme_minimal()
)
p.show()

Note we stored the plot in a variable — plots are ordinary objects in both languages, so you can print them, add more layers later (p + facet_wrap(~ cyl)), or save them to a file with ggsave() (in plotnine, the plot’s .save() method):

R

ggsave("week4_mpg_wt.png", p, width = 6, height = 4)  # inches

Python

p.save("week4_mpg_wt_py.png", width=6, height=4, verbose=False)  # inches

Change the extension to get a different format (.pdf scales beautifully in documents). If a figure looks wrong in your report, resize it here, in code — never by dragging its corner in a word processor.
